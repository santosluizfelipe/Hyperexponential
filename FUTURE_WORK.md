# Product Questions and Future Work

## Finance Point of View

The following questions would need stakeholder input before building a Finance approval workflow:

- What statuses should a proposal move through?
- Can Finance approve, reject, request changes, or edit a proposal?
- Is there a raise threshold that requires additional approval?
- Can Finance approve an out-of-band or over-budget proposal?
- Should Finance see both the proposed increase amount and percentage?
- What employee, salary-band, performance, and budget data can Finance access?
- Which decisions and changes must be recorded for audit purposes?

## What I Would Add With More Time

- **Team filters:** Managers could filter their reporting hierarchy by level, team, and salary-band status. This would help identify employees below band, compare similar roles, and focus compensation reviews on relevant groups.

- **Company-wide employee search:** Managers could search the complete employee directory using non-sensitive information such as name, role, team, and location. Compensation, salary bands, performance reviews, and proposals would remain available only to authorized managers.

- **Salary progression history:** Each employee profile could show previous salaries, raises, effective dates, and promotion history. This would provide useful context when reviewing a proposal without becoming an automatic approval rule.

- **Audit history:** The system could record important events such as proposal submissions, approvals, changes, salary-data access, and unauthorized access attempts. Each entry would identify the actor, action, target, outcome, and timestamp.
